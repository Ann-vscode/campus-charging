## 1. 现阶段能看到 / 验证的内容（已有功能点）

### 1.1 Gazebo 三维场景（R3.1，WSL 真实可跑）

启动后俯视可见一个 16m × 8m 的仿真场地：

| 场景对象 | 视觉呈现 | 可验证点 |
|---|---|---|
| A / B / C 停车区 | 蓝 / 绿 / 橙三块色块，白色车位分隔线（12/10/8 车位） | 与场景配置 `campus_basic.yaml` 的分区和车位数一致 |
| 基站 | 深蓝台座 + 立柱，位于 (7.0, 4.0) | 机器人初始 spawn 点 |
| 5 个充电桩 | 红/蓝/绿/黄/紫五根小柱，基站旁一排 | 五路独立充电的**物理占位** |
| 静态路障 | 2 面黄色隔墙（区之间）+ 3 根红色柱子 | R3.3 已用它们验证绕障与完全阻断 |
| 机器人 | 自包含差速车（本体 + 双轮 + caster + 激光 link） | spawn 成功、可被 Nav2 驱动到指定点（R3.2） |
| 传感器 | `/scan` 激光（3 m 量程）、`/odom` 里程、`/imu` | 话题可订阅、数据随运动更新，`/scan` 直接喂给 Nav2 costmap |

**已实测结论**：headless 启动成功，`Successfully spawned entity [campus_robot]`，`/cmd_vel` `/odom` `/scan` `/imu` 四话题齐全，0 致命错误。

### 1.1b Nav2 点到点导航与绕障（R3.2 / R3.3，WSL 真实可跑）

| 能力 | 做法 | 实测结论 |
|---|---|---|
| 点一下就走 | 静态地图（由 world 几何生成，320×160 px、0.05 m/px）+ Nav2（RPP 控制器 0.22 m/s、NavFn、inflation 0.28） | 三区各 3 次共 **9/9 到达**，最大误差 **0.191 m**（`results/r32_nav_trials.json`） |
| 手动放路障 | 面板小地图左键点一下即 `/spawn_entity` 生成 0.5×0.5×0.6 m 方块 | 出发前放到车与目标之间 → 绕行到达，误差 0.182 m、最小体表间隙 0.93 m（`results/figs/ui_obstacle_demo.gif`） |
| 中途插障绕行 | 脚本在车行进中插障（`nav2_r33_test.py --mode avoid`） | **3/3 到达**，最小体表间隙 0.08 m，0 碰撞 |
| 完全阻断 | 16 m 隔墙贯穿场地（`--mode block`） | **0/2 到达**，规划器持续报 `failed to create plan`（作为"无解"证据） |

> 定位口径：`map` 为静态地图、`map→odom` 恒等，**未启用 AMCL**，对外只说"里程计定位 + 点到点导航"，不要讲成 SLAM 或重定位。
> 能力边界：R3.3 是"静态插入路障 + 重规划"，**不含移动障碍**（人会走、车会动的那种），别讲成"动态避障已覆盖"。
> 雷达只有 3 m，所以面板上画了 3 m 虚线圈：圈内放立刻绕，圈外要等车开到 3 m 内才被发现。

### 1.2 前端监控界面（R1.3，Mock 模式零依赖演示）

浏览器打开即可用，无需后端、无需 ROS：

- **SVG 校园地图**：基站、三区车位、车辆编号与**电量颜色**、状态描边、机器人位置与朝向、规划/已走路径、静态与临时障碍
- **任务面板**：当前任务、目标 5 车、机器人状态与电量、本批进度 `x/5`
- **五路充电通道卡片**：每路独立状态，单车失败不遮其他通道
- **控制条**：启动 / 暂停 / 恢复 / 复位 / 倍速 1x·10x·60x / 添加临时路障（无死按钮）
- **事件日志**：17 类事件中文筛选，最新在上
- **顶部标识**："仿真模式 · 模拟车辆数据"

**一键流程**：点「启动系统」自动演进 —— 选车 → 派单/导航 → 到达对接 → 五路充电 → 充电完成 → 车辆离位 → 返基站 → 待命，全程无人工确认。导航中注入路障会进入 `REPLANNING` 并记录 `OBSTACLE_DETECTED` + `REPLAN_TRIGGERED`。

### 1.3 后端与遥测闭环（R1.2 / R2.1 / R2.2 / R2.3，命令行可验证）

- 12 个 HTTP 端点 + WebSocket `/ws`，统一响应信封 + 完整错误码（409/400/503/404）
- MockRobot 状态机：IDLE → NAVIGATING → DOCKING → CHARGING → DEPART → RETURNING → RECHARGING
- 调度打分（0.35/0.20/0.25/0.20）+ 跨区补位 + 能源模型 + 低电量返基站
- 车辆遥测上报：30 车模拟、29 帧上报（A03 离线被正确排除），jsonschema 校验通过
- **全量 pytest 72/72 PASS**；倍速能耗一致性 1x/10x/60x 均为 0.3053%

### 2.3 让机器人动起来 + 看数据

另开一个终端：

```bash
source /opt/ros/humble/setup.bash
ros2 topic list | grep -E '(cmd_vel|odom|imu|scan)'   # 确认话题
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.2}, angular: {z: 0.0}}'            # 发一次前进指令
ros2 topic echo /odom --once                          # 看位姿变化
rviz2                                                 # 加 LaserScan=/scan、Odometry=/odom 可视化
rqt_graph                                             # 看节点与话题连接关系
```

> WSL 无音频时 gzserver 会打印 ALSA `Unknown PCM default` 警告，不影响仿真，可忽略。

## 4. 对外介绍可用的功能总结

**30 秒版（电梯演讲）**
> 我们做的是校园共享电动车移动集群充电的**仿真系统**：车辆上报位置电量，平台自动选出最多 5 辆，机器人自主导航到车位、自动对接、五路同时充电，完成后离开，电量不足自动返回基站。目前三维场景、自主导航与绕障、监控界面、调度与能源模型都已跑通并有测试覆盖；下一阶段把导航接进业务流程。

**分点功能清单（可对外陈述）**

1. **物联网遥测**：30 辆仿真车周期上报位置/电量，离线与过期数据自动识别
2. **智能调度**：按电量、距离、区域、机器人余能加权打分，每批≤5 辆，可复现
3. **五路独立充电**：每路独立进度，单车失败不影响其他通道
4. **能源管理**：移动/充电能耗建模，低电量自动返基站补能
5. **三维仿真场景**：Gazebo 中三区车位、充电桩、基站、路障与差速机器人
6. **自主导航与绕障**：静态地图 + Nav2，面板点目的地即走（9/9 到达，误差 <0.2 m）；小地图手动放路障后自动绕行，完全阻断场景有"无解"记录
7. **实时监控界面**：地图、任务、充电、控制、事件日志一体化，投影友好
8. **仿真时钟**：单一时钟源，1x/10x/60x 倍速，演示可在数秒内跑完整流程
9. **可验证性**：72 项自动化测试 + 端到端自检脚本 + R3.2/R3.3 验收记录与轨迹图

> 每条陈述后都加一句"以上为仿真数据"，避免被误认为真实部署。
