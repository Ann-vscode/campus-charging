# 统一仿真参数基线

- **契约版本**：`v1.0.0`（与 `api.md` / `telemetry.json` / `state_machines.md` 同步）
- **状态**：FROZEN（冻结，变更走 `api.md` 第 8 节流程）
- **契约 Owner**：Kimi（系统负责人）
- **适用范围**：校园共享电动车移动集群充电**仿真**系统（非真实部署）

> 本文件补齐原方案「能源参数缺失」与「调度定性」缺口，给三条开发线提供**唯一数值基线**。
> 所有数据均为**仿真数据，非真实车辆数据**；所有对外响应必须按 `api.md` 携带 `simulation: true`。
> 参数分两类：**给定基线**（本次明确指定，不得擅改）与**仿真假设**（为让仿真可运行而设定，可配置但须显式标注）。

## 2. 机器人能源模型（R01）

### 2.1 给定参数

| 参数 | 符号 | 取值 | 说明 |
|---|---|---|---|
| 储能容量 | `E_cap` | `5.0 kWh` | 机器人车载储能总容量 |
| 初始 SOC | `SOC_0` | `100%` | 每次 `reset` 后恢复 |
| 移动能耗率 | `e_move` | `0.05 kWh / 100 m` | 即 `0.0005 kWh/m` |
| 充电效率 | `η_charge` | `0.95` | 储能 → 通道输出的转换效率 |

### 2.2 能耗计算（实现须按此式）

1. **移动扣能**：

   ```
   E_move = e_move × d / 100 = 0.05 × d / 100  (kWh)   // d 为行驶距离，单位 m
   ```

   机器人位置变化时按累计里程扣减储能：`SOC_new = SOC_old - (E_move / E_cap) × 100`。

2. **充电扣能**（机器人储能 → 通道 → 车辆电池）：

   ```
   P_store = P_ch / η_charge                    // 储能侧消耗功率
   P_bat   = P_ch × (1 - λ)                     // 车辆电池实际接收功率，λ = 传输损耗系数
   E_store = E_bat / (η_charge × (1 - λ))       // 交付 E_bat 给车辆需消耗的储能
   ```

   其中 `P_ch = 3.5 kW`（单路额定），`λ = 0.05`（见第 4 节）。两个系数**不得重复扣减**，按上式一次性折算。

3. **低电量返基站**：当 `SOC ≤ LOW_ENERGY_THRESHOLD` 时触发 `LOW_ENERGY` 事件，机器人转 `RETURNING`；阈值定义为**仿真假设**，默认 `20%`，可配置。

4. **补能**：到达基站（`ARRIVE_BASE`）且需补能时转 `RECHARGING`，按 `η_charge` 反向计算补能时间，`RECHARGE_DONE` 后恢复 `IDLE`。

### 2.3 派发可行性校验（强制）

派单前须估算「完成当前候选批次所需储能」：

```
E_est = E_move_total + Σ E_store,i
```

若 `E_est` 超过机器人当前可用储能（含安全余量，默认保留 `10%`），则**不派发**该批次，机器人先 `RECHARGING`。该规则对应任务卡「预计无法完成不派发」。

## 3. 车辆参数

### 3.1 给定参数

| 参数 | 取值 | 说明 |
|---|---|---|
| 车辆总数 | `30 辆` | 仿真场景内全部车辆 |
| A 区 | `12 辆` | 停车分区 A |
| B 区 | `10 辆` | 停车分区 B |
| C 区 | `8 辆` | 停车分区 C |
| 目标 SOC | `80%` | 达到即视为 `CHARGE_DONE` |
| 标准化自动对接接口 | **仿真假设** | 见 3.3 |

### 3.2 单车需电量

给定基线未提供单车电池容量，设定如下**仿真假设（可配置）**：

```
E_need = (SOC_target - SOC_current) / 100 × E_vehicle_cap
```

- `E_vehicle_cap` 默认 `0.5 kWh`（电动自行车量级，**仿真假设**）。
- `SOC_target = 80%`，`SOC_current` 取车辆当前遥测 SOC。
- 例：`SOC_current = 30%` → `E_need = 0.5 × 0.5 = 0.25 kWh`。

> 该默认值仅为让能源模型可量化验收；实际数值可在 `scenarios` 配置中覆盖，覆盖后须在场景元数据标注「仿真」。

### 3.3 标准化对接接口（仿真假设）

原方案「标准化自动对接接口」为抽象假设，落地为以下**仿真侧**量化阈值（均为**仿真假设，非真实车辆数据**）：

| 参数 | 默认值 | 说明 |
|---|---|---|
| 对接位置误差阈值 | `≤ 0.10 m` | 机器人对接位姿与车辆接口位姿的平面距离上限 |
| 对接角度误差阈值 | `≤ 5°` | 朝向角偏差上限 |
| 接口可用状态 | `AVAILABLE` / `BLOCKED` | 每位假设一接口状态，随机模拟中可置 `BLOCKED` |
| 对接重试上限 | `3 次` | 超限按 `RETRY_EXCEEDED` 处理（见 `state_machines.md` 机器人 R9） |

满足阈值 → `DOCK_OK`；否则 `DOCK_FAIL`，按状态机重试/重规划；重试超限则跳过该车并记录 `DOCK_FAIL` 事件。

## 4. 五路充电参数

### 4.1 给定参数

| 参数 | 符号 | 取值 | 说明 |
|---|---|---|---|
| 通道数 | `N_ch` | `5` | 五路独立充电 |
| 单路额定功率 | `P_ch` | `3.5 kW` | 从机器人储能取电 |
| 传输损耗系数 | `λ` | `0.05` | 通道到车辆电池的损耗 |

### 4.2 功率与充电时长

```
P_bat   = P_ch × (1 - λ) = 3.5 × 0.95 = 3.325 kW       // 车辆电池实际接收功率
P_store = P_ch / η_charge = 3.5 / 0.95 ≈ 3.684 kW      // 机器人储能侧消耗功率
t_charge = E_need / P_bat                                // 充电时长（h）
```

- 五路总标称输出功率 `5 × 3.5 = 17.5 kW`（储能侧约 `18.42 kW`）。
- 每路独立跑 `state_machines.md` 第 3 节通道状态机；通道状态须为 `EMPTY` 才可被占用。
- 充电过程中按 `t_charge` 推进车辆 SOC，达到目标 SOC 触发 `CHARGE_DONE`。

## 5. 调度打分公式（解决「可复现」缺口）

### 5.1 公式

```
score = 0.35 · S_lowSOC + 0.20 · S_avgSOC + 0.25 · S_dist + 0.20 · S_robot
```

| 分项 | 权重 | 定义（取值范围 0–1，越大越优先） |
|---|---|---|
| `S_lowSOC` | `0.35` | `1 - SOC_current / 100`，候选车辆 SOC 越低分越高 |
| `S_avgSOC` | `0.20` | `1 - zoneAvgSOC / 100`，所在分区平均 SOC 越低分越高（优先照顾整体低电区） |
| `S_dist` | `0.25` | `1 - d / d_max`，`d` 为机器人到候选车辆距离，`d_max` 默认 `100 m`（**仿真假设，可配置**） |
| `S_robot` | `0.20` | `robotSOC / 100`，机器人余能越充分分越高 |

### 5.2 可配置权重

- 默认权重向量 `W = (0.35, 0.20, 0.25, 0.20)`，总和为 `1.0`。
- 权重须从场景配置（`scenarios`）读取，允许覆盖；覆盖后四个权重之和仍须为 `1.0`，否则配置无效。
- 权重变更属**接口/配置变更**，按 `api.md` 第 8 节走 PR 与评审，不得在代码内硬编码分叉。

### 5.3 可复现性保证（强制）

1. 所有随机性（车辆离线、低电量、接口 `BLOCKED`）由 `seed` 驱动，默认 `20261118`，通过 `POST /api/simulation/start` 的 `seed` 传入。
2. 相同「场景 + 种子 + 权重 + 初始状态」必须产生**完全相同**的批次划分、派单顺序与结果。
3. 打分排序出现同分时，以 `vehicle_id` 字典序升序作为 tie-break，保证确定性。
4. 禁止使用未播种的随机数、当前时间、哈希随机化参与调度决策。

### 5.4 每批调度

- 每次最多选 `5 辆`（`≤ 5`），按 `score` 降序取前 5。
- 目标分区内有效车辆不足 5 辆时，按第 6 节跨区补位。

## 6. 跨区补位规则

### 6.1 有效车辆定义

候选车辆须**同时**满足：

1. 状态为 `PARKED`；
2. 遥测 `stale == false`（非陈旧）；
3. `status != OFFLINE`；
4. `SOC_current < 目标 SOC 80%`。

### 6.2 补位流程

1. 先在本分区内按第 5 节打分选取，最多 `5 辆`。
2. 本区有效车辆 **不足 5 辆**时，从其他分区（按分区中心到机器人当前位置距离由近到远）依次拉取有效车辆补齐。
3. 补位车辆同样按 `score` 参与排序。
4. **总数仍 `≤ 5`**：补位只补足缺口，不得超额；例如本区 3 辆，则最多补 2 辆。
5. 若全区有效车辆仍不足 5 辆，则按实际可用数量派发（允许少于 5），不得虚构车辆。

### 6.3 补位记录

每次跨区补位须产生 `TASK_ASSIGNED` 事件，`message` 中注明「跨区补位」与来源分区，便于前端与验收核对。

## 7. 品牌中性化（强制）

- 系统、文档、界面、事件消息中统一使用「**校园共享电动车**」。
- **禁止**使用真实品牌名（包括但不限于原方案中的「奥约」）。
- 车辆标识使用中性编号 `V-<分区>-<序号>`，机器人标识 `R01`，不含品牌信息。
- 答辩材料中即使已标注仿真，也不得出现真实品牌名。

## 8. 仿真假设与「仿真」标注清单

### 8.1 仿真假设（可配置，须显式声明）

| 参数 | 默认值 | 理由 |
|---|---|---|
| 单车电池容量 `E_vehicle_cap` | `0.5 kWh` | 原方案未给，供能源模型量化 |
| 对接位置误差阈值 | `≤ 0.10 m` | 原方案「标准接口」为抽象假设 |
| 对接角度误差阈值 | `≤ 5°` | 同上 |
| 对接重试上限 | `3 次` | 同上 |
| 接口可用状态 | `AVAILABLE`/`BLOCKED` | 模拟接口异常 |
| 低电量返基站阈值 | `20%` | 原方案未给 |
| 储能安全余量 | `10%` | 派发可行性校验 |
| 最大距离 `d_max` | `100 m` | 距离分归一化 |
| 随机种子 `seed` | `20261118` | 保证可复现 |
| 场景坐标系 | 平面二维，单位 m | 仿真场景简化 |

### 8.2 必须标注「仿真」的数据（对外呈现时）

| 数据 | 标注方式 |
|---|---|
| 所有 HTTP 响应 | 信封字段 `simulation: true` |
| 所有 WS 消息 | 消息体字段 `simulation: true` |
| 车辆遥测 `VehicleTelemetry` | 描述/事件消息中标注「（仿真数据）」 |
| 机器人遥测 `RobotTelemetry` | 同上 |
| 任务事件 `TaskEvent.message` | 文本含「仿真数据」 |
| SOC、充电时长、能耗结果 | 图表/界面标题标注「仿真结果」 |
| 实验图表与价值分析 | 注明「仿真结果不能直接证明实际成本更低」 |

### 8.3 边界声明

- 本系统为**仿真**系统，不涉及真实插枪、真实高功率充电、真实车辆对接。
- 所有能耗、时长、SOC 均为模型计算值，**非真实车辆数据**，不得用于实际工程验收或成本结论。
